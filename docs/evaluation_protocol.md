## 手順
1. 開発用で規則を改良する（Node または評価モード）。
2. 区切りのよいところ（版を上げるとき）で評価用を 1 回実行し、「集計 JSON」「詳細 CSV」「クロス表 CSV」を `results/vX.Y/` に保存して commit する。
3. 品詞評価は UD 規約あり／なしの両方を保存する。
4. 評価用の誤りを**見て規則を直してはいけない**。誤りの「文法項目」の分布（grammar_tag 列）だけを見て、その項目の文を開発用に新しく書いて改良する。

### v1.0 で行った改良（解析規則は変更なし。訳と表示の仕上げ）
- 公開ページで AI 翻訳（FuguMT）がブラウザ内で動作することを確認（Windows / Edge。Technology 長文 12 文すべてに訳が付く。`results/v1.0/` の比較 CSV と同じモデル）
- 構造訳の修正: 辞書の訳語を「・」「；」でも区切って 1 義に（set → 置く・すえる・… が 1 語に）、参照見出し（relationship → =relation 1）の解決、活用形からの見出し推定（weekends → weekend、abandoning → abandon ＋「こと」）、句動詞辞書（turn off → 消す、set aside → 取っておく など 40 件）、ハイフン語（hyper-connected、phone-free、face-to-face …）と IT 語彙（digital、screen、smartphone、internet、online …）の上書き辞書、所有格 's（today's → 今日の）、役割に含まれない並列述語の後半を訳に含める、動名詞の受動（being overwhelmed → 圧倒される）。辞書カバー率 99.3% → 99.8%
- 表示: AI 翻訳をオンにすると構造訳を自動で隠す（チェックで再表示可）。構造訳は常に計算して JSON に残す。前回 AI 翻訳をオンにしていれば次回は自動で読み込む（キャッシュからなのでオフラインでも可）。見出し行の "Reading Passage:" などのラベルは翻訳対象から外す（モデルが「読書の過去」と誤訳するため）
- 既知の限界（FuguMT）: 慣用表現の直訳（comes with a price → 「価格が付属します」）、まれな未知語。構造訳の限界: 多義語の選択、節内の語順

### RQ5: ルールベース（構造訳）と小型ニューラル翻訳（FuguMT）の比較（評価用 163 文、`results/v1.0/translation_comparison.csv`。v0.9 の値も `results/v0.9/` に保存）
| 方式 | 仕組み | サイズ | 1 文あたりの時間（Node, CPU） | 出力の性質 |
|---|---|---|---|---|
| 構造訳 | 文型の役割＋辞書 1 義目を機械的に並べ替え | 辞書 3 MB | 0.75 ms（v1.0: 0.99 ms） | 語順は日本語だが語の選択・活用が不自然（bark→吠える は上書き辞書による） |
| FuguMT（q8） | Transformer（Marian）ニューラル翻訳 | 145 MB | 251 ms（v1.0: 248 ms。初回ロード 2〜12 s、ブラウザでは約 12 s） | 自然な日本語。まれに未知語（bark→「barえます」） |

速度差は約 300 倍、サイズ差は約 50 倍。構造訳は「構造を見せる」目的、FuguMT は「意味を確認する」目的で使い分ける設計とした。

### v0.3 の誤り分析（評価用 29 件、grammar_tag の集計）

## 処理時間の記録
初回の 1 文は JIT の暖機で数十 ms かかる。平均値を出すときは最初の 1 文を除くか、2 回実行して 2 回目を採用する。端末名・ブラウザ名を JSON の userAgent から転記する。
